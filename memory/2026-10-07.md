# 2026-10-07

## xread 书海页「平台」筛选下拉修复（16:00-16:35）<!-- project: github.com/Charmillionaire/reader-rust -->
- **现象**：书源「光遇聚合」(bookSourceUrl=光遇聚合，显示名 `🔅光遇聚合26.9.29`) 的 `getExploreKinds` 返回中，「平台」控件 `chars` 为 null、`default` 为「番茄」，前端下拉只能显示默认值；「线路」「类型」「频道」等控件 chars 正常。
- **根因（关键）**：exploreUrl 脚本里写的是
  ```js
  js = getVariable('云端配置');
  if (!!!js) { getCloudSettings(true); js = getVariable('云端配置'); }
  ```
  后端 `DEFAULT_VARIABLE_JSON` 预置的对象是**非空对象**，JS 里对象恒为 truthy，所以 `!!!js === false`，`getCloudSettings(true)` **永远不会被调用**。于是 `getVariable('云端配置')['小说']` 是 undefined，`createFilter("平台", source_list, sources, "发现页来源", 1, "'平台'")` 的 chars 变成 null。
  - 验证要点：`!!!x` 只有在 x 为 `null` / `undefined` / `""` / `0` 等 falsy 时才为 true；`{version:"", hosts:[...]}` 是 truthy。
  - `getCloudSettings` 逻辑：`let c = getVariable('云端配置').version; if (r || !c) { ...拉 /static/source_config/config.json... 比较 version ...}`，即 `version` 为空是「尚未同步」的标记。
- **修复**（commit `3638991`，已推 `Charmillionaire/xread` master）：
  1. `src/parser/js.rs` 新增 `pub fn eval_explore_script(script, base_url)` + `CLOUD_SETTINGS_SYNC_PREAMBLE`：求值发现页脚本**前**，若 `云端配置.version` 为空且书源定义了 `getCloudSettings`，先调用 `getCloudSettings(true)` 拉取真实配置；书源无此函数时空操作。
  2. `src/parser/js.rs` 补全 `DEFAULT_VARIABLE_JSON`，加入 小说/听书/漫画/短剧 四个分类的平台列表（`version` 刻意留空作为「尚未同步」标记），云端同步不可用时也有候选兜底。
  3. `src/service/book_service.rs` `parse_explore_kinds` 改走 `eval_explore_script`（原来直接用 `eval_js`）。
  4. 回归测试：`src/parser/js.rs` 单元测试 `default_cloud_config_exposes_platform_choices`；集成测试 `tests/gy_explore_platform.rs`（需 `/tmp/gy_source.json` 真实书源样本，缺失则跳过）。
- **验证结果**：
  - 本地 `cargo check` 通过；`cargo test --lib` 55 passed。
  - NAS 实测 `POST /reader3/getExploreKinds {"bookSourceUrl":"光遇聚合"}`：平台 **57 项**（含七猫/塔读/QQ阅读），线路 7 / 类型 4 / 频道 2 / 字数 10 / 更新 7 / 排序 4，无回归。
- **部署路径（重要，与 release.sh 不同）**：改代码 → push `Charmillionaire/xread` master → GitHub Actions `.github/workflows/build.yml` 自动构建推 `ghcr.io/charmillionaire/xread:latest`（linux/amd64，用 `secrets.GHCR_TOKEN` 登录 GHCR）→ NAS 上 `cd /vol1/1000/xread && docker compose pull && docker compose up -d`。
  - NAS `/vol1/1000/xread/docker-compose.yml` 的 image 是 `ghcr.io/charmillionaire/xread:latest`，**不是** `scripts/release.sh` 里的 `docker.io/givenge/reader-rust`。做发布时别用错仓库。
  - NAS 是 x86_64；本机没有 podman/docker，且缺 `x86_64-linux-musl-gcc`，所以走 CI 构建而不是本地 build。
  - 容器内二进制路径 `/app/reader-rust`，storage 挂载 `./storage:/app/storage`，`PUBLIC_READ=true`。
- **排查手法备忘**：书源脚本可从后端接口直接导出，方便本地复现：
  - `curl -s http://192.168.1.123:7777/reader3/getBookSources | jq -r '.data[] | select(.bookSourceUrl=="光遇聚合") | .exploreUrl'`（同理 `select(.jsLib)`）
  - `sqlite3` 不能直接读 OpenClaw 状态目录下的库；NAS 上没装 sqlite3；本轮改用 HTTP 接口取书源，最省事。
- **教训**：书源 JS 用 `!!!x` 判断「是否已初始化/已同步」，后端预置默认值时**不能只给 hosts**，否则会静默短路掉书源自己的同步分支，表现为某个筛选项 charL 为空但不报错。以后核验书源发现页，要检查「默认变量是否让书源的惰性初始化分支失效」。
